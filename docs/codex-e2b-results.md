# Authenticated Codex filesystem recovery on E2B (#249)

Measured 2026-10-03: two real filesystem-only pauses and authenticated resumes
passed for one minimal Linux Codex thread. The final independent reference
receiver held **97 ordered records, 165,912 bytes, no loss or duplicates**.
This qualifies the small personal experiment, not production hosting, arbitrary
thread recovery, or the durable runtime integration proposed in #250–#256.

## Work and recovery outcomes

The first authenticated task implemented a Python integer-duration parser and
six tests, all passing. A marker supplied only in the conversation was recalled
after both cold boots without a tool reading harness files. The workspace-write
sandbox denied the agent's Git commit because `.git` was read-only. At the
completed turn, the coordinator committed the implementation/tests, then added
a tracked uncommitted comment. The untracked `notes.txt` and generated bytecode
were retained too. Git HEAD remained
`251f113607e6aa27a00de4653600d374d31aa883` through both boots.

The first command using obsolete `--full-auto` failed argument parsing with exit
2 before any thread receipt; the supported workspace-write command then ran
once. That authenticated turn emitted `turn.completed`, but the background
wrapper did not provide a usable process-exit record. Its stale exit file from
the argument failure was excluded as evidence. Delivery was not replayed. Both
subsequent foreground resumes explicitly closed stdin and returned exit 0.

Pause used `sandbox.pause(keep_memory=False)` with explicit manual `connect()`
resume. The first paused state was independently observed in the provider list.
Before that pause, Push PID 2410 and idle native Codex app-server PID 2531 were
live; after reboot neither was present. The completed exec harness had already
exited. An idle app-server supplied live harness process-loss evidence without
pausing an active tool. Push was restarted manually against the same binding
and retained cursor. No active tools or permission requests were suspended.

A separate held Linux `flock` on `thread-writer-locks/<thread>.lock` made a
competing resume exit 1 with `already has an active writer`; it emitted no turn
or tool events and left the original rollout unchanged. The lock was released
before work resumed. There were no competing workspace writers in this isolated
experiment. This does not supply coordinator epoch/workspace fencing.

## Qualified recovery set and SQLite behavior

The first boot retained the entire filesystem. For the second, the full Codex
home was set aside inside the same owned guest. The configured home was rebuilt
at the same absolute path using only the original rollout and the already
authorized guest's authentication file, copied with mode 0600. No prior SQLite
database or config was installed. `login status` generated temporary launch
helpers, but database inventories before and after that boot were empty.
The original full home remained available as protected fallback; this was not
an independent-storage VM reconstruction test.

Resume reconstructed `state_5.sqlite` with one thread row pointing at the stable
rollout/workspace paths, and `thread_history_1.sqlite` with three turns and
24 items. Earlier retained-disk inventories had one turn/12 items, then two
turns/18 items. Other initialized databases were logs, goals, memories and
queue. Exported databases used SQLite's backup API; live WAL files were never
raw-copied. No unrelated target threads or stale absolute-path index were tested.

For this thread, the smallest exercised historical recovery input was the
**original rollout plus workspace**, with authentication available separately
and the pinned executable already installed. This is not a claim that auth can
be discarded or that all Codex history is reconstructible from a rollout.

## Push readback and identity

The receiver was an unmodified `semon receive` in separate compute. It listened
on loopback behind a small [experiment-only HTTP proxy](../tests/spikes/e2b-mirror-proxy.py)
through E2B's HTTPS ingress. The reference receiver's token authentication still
guarded every append/facts request. The receiver sandbox's ingress was created
with `secure=False` because Push cannot supply E2B's separate ingress token;
model credentials and provider credentials were never placed there.

Readback used Semon's actual `semon_push::redact::redact` implementation on the
downloaded original, then compared every byte with the receiver. In this sample
redaction changed no bytes. Original, expected and receiver SHA-256 were all
`3fb2c425a23d6c0a871b23e70c1fe290a6ee3750c679455a1d1b173d9b5b5bd9`.
The 97 records had unique, increasing ordinals 0–96 and zero identical duplicate
lines. Both source and receiver models showed exactly the same one session ID,
with one turn initially and three turns finally, under the unchanged binding.

The final Push pass reported `1 files, 165912 bytes, 1 sent again whole`:
the source had been rewritten during minimal-home recovery. Existing replacement
and cursor reconciliation produced the exact final mirror without a new WAL or
transport change. Facts initially made the receiver report `work` after local
completion; stale process facts do not determine logical-session lifetime.
This experiment does not qualify receiver rollback or hosted hub ACK durability.

## Reproduction and evidence retention

Follow [the procedure](codex-e2b-qualification.md), pin the versions above, and
use `--sandbox workspace-write` rather than obsolete `--full-auto`. Close stdin
on foreground exec/resume (`</dev/null`) and retain each fresh exit record.
Use distinct prompt IDs and persist `thread.started`; never replay a turn just
because the command wrapper's outcome is missing.

Install Codex under a separate guest prefix, authorize the guest home via device
login, and keep the workspace/home/binding stable. For the smaller-set test,
quiesce writers, move the full home aside, recreate the same home path, install
only the original date-relative rollout and protected guest authentication, and
confirm there are no SQLite files before pause. Preserve the original home
until all restore checks succeed. Hash all workspace files (including `.git`,
untracked and uncommitted files) and rollouts on both sides of each boot. Use
SQLite backup APIs for export. Final byte verification must use Semon redaction,
not an assumed equivalence between originals and redacted mirrors.

Protected original evidence was exported outside both sandboxes and SHA-256
verified before cleanup. Archive manifests exclude `auth.json`, Push token
files, and the E2B key; archives are held in the worker's restricted evidence
directory, not committed to this public repository:

- Source archive: `19bcced9702403d38fba37c46c2db6ccfc91665c2d2ad458492ee1032c02e242`.
- Receiver archive: `f6b1e78eefd088b93226d88e1f4dd64782828c6010c5bfbd0528ba0b49e99dc8`.

After verifying ownership labels and those exports, both owned sandbox kills
returned true. Cleanup deletion of experiment compute is not qualification of
production deletion/reconstruction; #255 still gates that capability.

Unqualified cases remain compaction, long/paginated-history stress, attachments,
subagents, pending tools, active permission waits, other CLI versions, non-Linux
locks, unrelated target indexes, auth refresh/expiry, controller crash races,
durable inbox delivery, and hosted hub storage/readback. The rollout advertised
`history_mode: paginated`, but only this three-turn history was exercised.
