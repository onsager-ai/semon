# Codex native state evidence and reader boundary

This note maps the pinned Codex storage sources to the narrow native-state evidence Semon could safely consume. The upstream source pin is [openai/codex `a9b0815167c27ab13719dd12d13b63e02b70d221`](https://github.com/openai/codex/tree/a9b0815167c27ab13719dd12d13b63e02b70d221); it does not establish which version created any local database.

A parent-reported, bounded stat-only sample on 2026-10-13 observed the standard state, goals, memories, logs, history and queue database files under one default root; it did not observe `memories_v2_1.sqlite` there. No database was opened and no table, schema version or row was read. Relocated roots, the live database schema and alignment between the installed CLI and the source pin remain unverified. This is a local existence observation, not a native capture.

At this revision, SQLite root resolution prefers configured `sqlite_home`, then `CODEX_SQLITE_HOME`, then the resolved `codex_home`; the environment value is trimmed and resolved against `resolved_cwd`. The SQLite layer derives database filenames from the selected root. [Config resolution](https://github.com/openai/codex/blob/a9b0815167c27ab13719dd12d13b63e02b70d221/codex-rs/core/src/config/mod.rs), [SQLite paths](https://github.com/openai/codex/blob/a9b0815167c27ab13719dd12d13b63e02b70d221/codex-rs/state/src/sqlite.rs), [environment variable](https://github.com/openai/codex/blob/a9b0815167c27ab13719dd12d13b63e02b70d221/codex-rs/state/src/lib.rs). Resolve that configuration under the host's permission boundary. A rollout path does not authorize access to neighboring state files or an arbitrary sibling home.

Semon currently derives Codex metadata from the first physical `session_meta` rollout record and allow-lists fields such as `parent_thread_id`, `agent_path`, `thread_source`, `cwd` and branch; the tree summary also reads rollout events. It does not read the mutable SQLite name or project rows. See [`native_header.rs`](../../crates/semon-sessions/src/native_header.rs), [`model.rs`](../../crates/semon-sessions/src/model.rs) and [`native_tree.rs`](../../crates/semon-sessions/src/native_tree.rs). Keep source-bound header facts primary for the original rollout. Any SQLite enrichment must carry its own selected database identity and observation time; it cannot rewrite that header or serve as rollout provenance. This boundary follows the existing [`SessionSourceReader` contract](session-source-reader.md), where a source reference does not grant authority and every request is reauthorized against the current source generation.

The small [synthetic contrast fixture](../../tests/fixtures/compatibility/codex-local-evidence-a9b0815/capability-matrix.json) records the pre-0041 and post-0041 schema shapes, a same-ID/two-home case, a conflicting exact spawn edge, and valid/missing/unsupported worktree-owner records. It is schema-qualified research data, not two tested Codex versions, a native capture or an executable test fixture.

## Proposed P0 boundary

This documentation slice does not implement native SQLite reading. The proposed P0 is one request-scoped, exact-ID selection that returns source identity, schema/migration fingerprint, observation time, and explicit `available`, `unavailable`, `stale`, `ambiguous` or `conflict` outcomes. It resolves only the configured and authorized SQLite root, accepts a fixed structured selection rather than free-form SQL, opens a read-only WAL-consistent view, performs no migration, recovery or checkpoint, bounds selected rows/bytes, caller instruction text and the whole operation, and rejects symlink traversal or file replacement across open and query. Unknown schemas, lock contention, mismatched IDs and conflicting lineage fail closed; the call never scans adjacent homes or all sessions.

Adapter integration remains deferred while Semon #380 settles its source interface. The P0 gap is real but separate from the #380 launch gate. The current Codex native-evidence lane owns follow-up; resume implementation only after the existing Claude weekly-reset hold is verified lifted and an Opus-qualified security/concurrency/authorization route is available. An independent diff review and locked CI coverage for read-only behavior, active WAL, contention, no writes, path authorization/replacement, migration boundary shapes and evidence conflicts are required. The hold prevented that implementation dispatch here. No runtime adapter, CI change or live database read is part of this source-only note.
