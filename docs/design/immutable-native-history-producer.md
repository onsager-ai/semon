# Selected immutable native History backfill

`publish_immutable_history_source` accepts one host-authorized descriptor and a borrowed `HistorySourceReader`. The descriptor names a logical root/path, exact full logical SHA-256 generation and length. It supplies no native identity, local stat, credentials or control authority.

The producer reads sequential ranges of at most 128 KiB, independently hashes all logical bytes, then calculates the complete-line consumed offset, full consumed-prefix SHA-256 and last-4-KiB tail SHA-256. Native identity comes from parsed native metadata. The host must authorize each callback, including cache hits and the two empty EOF callbacks (after acquisition and immediately before publication). Its deadline, cancellation and custody lease must cover the whole operation and post-publication verification.

The shared Claude/Codex event handlers and native session/turn builder prepare source-only summaries and untrimmed recipes. Verified original bytes remain operation-local; no physical device/inode/timestamps are invented. Persistent source metadata carries `immutable_generation`; local sources continue to serialize their existing numeric physical fields unchanged. Selected transcript rendering always calls the host reader for an immutable origin, even when a local file exists at the same path, and checks the pinned generation.

The publication checks the catalog generation captured before acquisition, current store version and selected-path invalidation inside one SQL transaction. It writes retained metadata and History recipes together, advances the durable collection epoch, and preserves the source/native mapping. The default Current list excludes this retained row. Exact identity carries a null native ID and provisional owner qualification; these recipes grant no native controls, execution, resume or environment recovery. Missing relationship context remains explicitly incomplete. Returned projection evidence and source references describe what was actually committed.

Initial limits are 64 MiB per original, 16 MiB per native record, and 4,096 complete records/events and slots. Claude top sessions and Codex rollouts are supported. Unsupported subagent context, missing/ambiguous native metadata, budget overflow and conflicting current owners fail without a projection. The API does not walk roots, restore unrelated event indexes, copy an archive into the workspace or initialize a ViewerCore.

An existing different canonical owner/metadata is currently a conflict rather than a guessed lineage merge. Later local observation at the same canonical key/path must not overwrite an immutable History recipe: publication remains blocked until a qualified multi-generation same-path merge exists. Different-path disappearance continues through the existing retained-lineage publisher. This limitation keeps the original generation readable; it does not complete archive lineage support.

Qualification covers actual Claude question/answer and Codex native tool output through the provider reader, partial-tail prefix proof, no local native file or event ledger, no Current list/control authority, no stored bodies, reopen/full-background retention, conflicting local replacement, false full-SHA claims and authorization expiring after native preparation. Hosted access, object layout, tenancy, authorization and custody remain outside public Semon.
