# Pinned Codex native conformance oracle

This fixture checks Semon's source-shaped rollout expectations against the actual public reducer from openai/codex commit a9b0815167c27ab13719dd12d13b63e02b70d221. CI copies the original runner from tests/spikes/codex_native_oracle.rs into a disposable upstream checkout, constructs a bundle with the upstream TraceWriter, and calls the upstream replay_bundle reducer. It does not modify upstream source files, start the Codex runtime, call a provider, or use a paid Codex session.

The fixture at tests/fixtures/compatibility/codex-reference-a9b0815 has separate Legacy and Paginated rollout JSONL, a synthetic trace-events.jsonl, and a manifest with the normalized reducer graph and edge classes. Both the default rollout and trace fixtures describe the same sequence: a direct model `exec_command` starts process `26789`, then one outer code cell starts `95583` and polls `26789`. The fixture declares a non-login `/bin/sh` shell, so the model-visible `printf old/new` commands appear as `[/bin/sh, -c, ...]` in runtime and Paginated command vectors. Its printed output is a three-part array containing the success header, the new-process JSON, and a completed-poll JSON without a `session_id`. The oracle checks the exact call/output pairing in inference input and output, the code-cell source string, and the corresponding nested dispatch evidence. Exec starts use native begin/end payloads with required fields; the empty `write_stdin` poll uses its canonical invocation (`session_id`, `chars`) and Code Mode result. The pinned recorder emits no exec begin/end for an empty completed poll, so the trace does not invent those events. Runtime envelopes and payloads retain the same emitted `call_id`; the direct operation uses `start-26789` in both. Synthetic clock and duration fields qualify the producer shape, not an observed duration. It does not pair printed blocks with runtime operations by position. The default rollout inputs contain no generated timestamps. The trace writer adds wall-clock fields only to the disposable temporary bundle; the comparison excludes them. Its origin is explicitly source-shaped synthetic, not a runtime capture, and the pin does not qualify any installed Codex CLI version.

## Field and relation map

| Carrier | Field | Meaning for Semon |
| --- | --- | --- |
| ResponseItem FunctionCall or CustomToolCall | call_id | Model-visible invocation identity; match its output by the same call_id. |
| ResponseItem FunctionCallOutput or CustomToolCallOutput | call_id, output | Completion belongs to the matching invocation. Output may be text or structured content. |
| ResponseItem Message | content[] | Ordered content parts. Preserve stored order and keep text, image, audio, and encrypted parts distinct. |
| CodeCellStarted | model_visible_call_id | Links a code cell to its outer model-visible exec call in the trace reducer. |
| ToolCallStarted | tool_call_id, requester, code_mode_runtime_tool_id | Runtime-local nested tool identity and requester. These requester fields are absent from the default rollout fixture. The native runtime call ID can separately survive as `CommandExecution.id` in Paginated history. |
| ToolCallRuntimeStarted/Ended | runtime payload call_id, process_id, source, command | Runtime evidence for tool execution and terminal identity. The process_id is not a model-visible call_id. |
| TerminalOperation | tool_call_id, terminal_id | Trace reducer's operation-to-tool and operation-to-session links. This fixture marks them trace_only for Semon's default parser. |
| CommandExecution | id, process_id, command, cwd, parsed_cmd, source, aggregated_output | The pinned emitter sets `id` to the native runtime call ID: this completed item identifies `tool-new` exactly and carries terminal process `95583` and its command result. Its ID supplies no outer CodeCell requester or model-visible invocation relation. Preserve parsed_cmd for existing consumers; the pinned public `TurnItem` enum checks the required source and path shape. |
| FileChange | item fields | A separate completed item; retain the source fields when present in the selected history mode. |

Code-mode callback IDs such as tool-1 are runtime-local. The upstream reducer joins them to the outer code cell from typed requester events and joins terminal operations to sessions from runtime or canonical dispatch payloads. The completed Paginated `CommandExecution.id` also preserves the exact runtime call ID (`tool-new` here), because both the completed-item emitter and trace emitter use the same native call ID. That carrier alone does not supply the CodeCell requester or model-visible invocation identity. Semon's default rollout reader does not ingest that trace bundle, so those reducer edges must not become expected parser edges or be reconstructed from neighboring text. The fixture separately marks exact call_id, completed-item runtime-ID and source-contract process joins as recoverable, output-order-only joins as ambiguous, missing default-carrier fields as absent, and reducer-only runtime links as trace_only. Recoverable means the carrier supplies exact evidence; it does not claim that the current Semon adapter projects every such field. The direct tool emits formatter text (`Chunk ID`, `Wall time:`, `Process running with session ID`, `Output:`), while Code Mode returns structured JSON to the outer script and a `Script completed\nWall time ...` header. These producer contracts cannot be interchanged. Semon decodes a strict, bounded direct formatter header only for a unique unnamespaced `function_call` named exactly `exec_command` or `write_stdin` paired with its exact `function_call_output`; exit zero and nonzero provide known outcomes, and a session-only header stays unknown. The decoder stops at `Output:` and treats the body as opaque. Explicit namespaces, IDs reused by another source call at the time an output is qualified, malformed headers, other call names, and Code Mode output do not qualify; an earlier result qualified while its ID was unique remains known. The session ID remains source evidence only: Semon does not use it to infer terminal liveness, ownership or grouping. The separate Paginated completed command carries exact runtime tool ID `tool-new` and process `95583`, but the current adapter does not project an unowned standalone completed command. Both capability gaps are explicit in the manifest; neither is repaired by guessing a relation from prose or output order.

## Persistence by history mode

The pinned rollout policy is mode-sensitive. ResponseItem FunctionCall, FunctionCallOutput, CustomToolCall, and CustomToolCallOutput records persist in both modes. In Legacy mode, completed ItemCompleted records persist only for FunctionCallOutput, Plan, Extension(Sleep), and completed SubAgentActivity; CommandExecution and FileChange are not durable there. In Paginated mode, completed items persist, including CommandExecution and FileChange. Paginated CommandExecution aggregated_output is middle-truncated when it exceeds 65,536 bytes, with a persistence marker.

TokenCount, ThreadGoalUpdated, ThreadRolledBack, TurnAborted, TurnStarted, TurnComplete, and ThreadSettingsApplied events persist in either history mode. ContextCompacted event messages are Legacy-only, while ContextCompaction response items and the Compacted, TurnContext, TokenUsageRecord, WorldState, RetainedContext, SecurityRiskScore, and SessionMeta rollout markers persist. ExecCommandBegin/End, TerminalInteraction, ExecCommandOutputDelta, Error, ItemStarted, and similar in-progress events are transient. RealtimeItem records persist only in Paginated mode.

The output truncation helper can render a warning header with original token and line counts before a middle-truncated excerpt. When Semon presents content, it should preserve the source's ordered content parts and treat that header as truncation metadata in text, not as a process ID or structured completion status.

## Running and updating the oracle

The conformance workflow checks out the exact pull request head SHA and the pinned Codex commit and installs the upstream-pinned Rust 1.95.0 toolchain with clippy, rustfmt, and rust-src. Independent jobs run the focused locked Semon event and transaction tests, both `codex_reference_conformance` hooks, `catalog::tests::selected_output_expansion_keeps_native_blocks_under_source_generation`, and `model::tests::parser_cache_reset_rederives_direct_formatter_catalog_outcome`, and copy/run the oracle example in the upstream checkout with its existing lockfile. The cache-upgrade test requires a coherent `Unknown` projection from cache version 25 to remain readable, then verifies a known publication at cache version 26 while preserving native identity and source fences. This keeps Semon test results from suppressing the upstream reducer comparison. The example reads the checked-in fixture directory and writes only to a new temporary bundle directory.

To replay the fixtures from a disposable checkout already at the pin, copy the runner into codex-rs/rollout-trace/examples/semon_native_oracle.rs and run this from codex-rs:

~~~sh
cargo run --locked -p codex-rollout-trace --example semon_native_oracle -- \
  /path/to/semon/tests/fixtures/compatibility/codex-reference-a9b0815 \
  /tmp/codex-native-reference-bundle \
  /path/to/semon/tests/fixtures/compatibility/codex-native-a9b0815/parser-cases.jsonl
~~~

The example derives the reduced graph from TraceWriter and replay_bundle, then compares it to expected_upstream_reducer in manifest.json. It also checks that reduced source/output item IDs resolve to the exact outer custom-tool call and result, that nested requesters name the reduced code-cell ID, and that the direct tool's call/output IDs resolve to its function-call items. The Paginated fixture's completed `CommandExecution` is a separate source-compatible carrier for process `95583`; its native item ID is checked against the paired runtime payload `call_id` and trace `ToolCallID`, while its process ID, command and output are checked against the paired trace and printed JSON. This exact native runtime identity is recoverable, but it does not establish model-visible invocation or outer CodeCell ownership and is not Legacy data. The Semon hooks use the same paired manifest and rollout files through the production event scan/cache and selected-output source reader. They compare exact model call/output IDs, cold/reopened cache evidence, source byte coordinates, and the ordered header/new-result/completed-poll blocks and native ordinals within the 64 KiB selected-output budget. They require the mixed cell to remain visible and unfolded with no nested IDs, yielded session or poll attachment, and verify that the separate Paginated source remains unowned. This is a carrier-aware differential comparison, not equality with the trace-only graph. The optional third runner argument typed-decodes only completed `CommandExecution` rows in the separate parser-cases fixture; deliberately unknown output-content negatives are not deserialized as known protocol variants. Update the expected graph only from the pinned reducer's actual output. Keep the carrier modes and edge classes explicit when changing a fixture. The delivery branch is stacked on parser correction #435 (`7ffbccbd8a5b55829725aed4f8294fd41d0cdd4d`), then oracle #434 (`c187c7cca6dce09ba7e3bdb4cef9bcc76aa04c37`), atop the pinned #380 foundation; the current direct formatter slice follows those prerequisites. Integration must retain those parser prerequisites or apply their reviewed successors once #380 interfaces stabilize. To refresh, choose a new exact upstream revision, audit the formatter/runtime/persistence contracts, update both carriers together, and run the independent reference job plus paired Semon hooks before changing the normalized expectation. A real native runtime capture has not been run; this oracle establishes only the checked synthetic contract at the pinned source revision.

## Pinned source map

- codex-rs/rollout-trace/src/protocol_event.rs and thread.rs define native exec trace fields, native-path cwd serialization and emitted call identity; tool_dispatch.rs defines canonical invocation/result carriers used by the empty poll.
- codex-rs/rollout-trace/src/raw_event.rs defines the raw trace envelope, code-cell events, and runtime requester records.
- codex-rs/core/src/tools/context.rs defines `ExecCommandToolOutput::response_text` and the distinct `code_mode_result`; `function_tool_response` turns a single input-text part into the direct text body. codex-rs/core/src/tools/code_mode/output.rs defines the normal and experimental timing headers.
- codex-rs/core/src/unified_exec/process_manager.rs marks process starts as `unified_exec_startup`; codex-rs/core/src/tools/events.rs carries the source, command vector, cwd and parsed command into `CommandExecution` items, and sets their `id` to `ctx.call_id`; protocol_event.rs emits that same native call ID as the runtime `ToolCallID` and payload `call_id`.
- codex-rs/rollout-trace/src/reducer/code_cell_tests.rs and reducer/tool/terminal_tests.rs show the upstream reducer joins for code cells, nested tool calls, terminal operations, and sessions.
- codex-rs/rollout/src/policy.rs defines Legacy and Paginated persistence and the 65,536-byte command-output limit.
- codex-rs/protocol/src/models.rs defines ordered content vectors and function-output payload shapes.
- codex-rs/utils/output-truncation/src/lib.rs defines formatted truncation headers and content-item handling.
- codex-rs/code-mode-runtime/src/runtime/callbacks.rs assigns runtime-local tool IDs.
- The [upstream LICENSE at the pinned commit](https://github.com/openai/codex/blob/a9b0815167c27ab13719dd12d13b63e02b70d221/LICENSE) is Apache-2.0 (blob 4606e72e042564097e8780d66c1d4dcb611869bd). The runner is original Semon code and does not vendor or copy upstream reducer implementation.
